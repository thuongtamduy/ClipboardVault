# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ClipboardVault — a SwiftUI macOS clipboard-history app (menubar + main window). Swift 6 toolchain, targets macOS 13+. The README is written in Vietnamese; user-facing copy in `Sources/main.swift` is also Vietnamese.

## Commands

- `swift run` — build and run the executable directly (will not be a proper `.app` bundle; menubar/launch-at-login features behave best when run from a bundle in `/Applications`).
- `./build_app.sh` — `swift build -c release` + assemble `ClipboardVault.app/` with `Info.plist` (`LSUIElement=true`) and icon, then ad-hoc codesign (required so `SMAppService` accepts the bundle).
- `./create_icns.sh` — regenerate `app_icon.icns` from `app_icon.png`.
- `swift test` — runs the swift-testing suite under `Tests/ClipboardVaultTests/` (uses `Testing`, not XCTest, because Command Line Tools ship `Testing.framework` but not `XCTest`).
- `swift test --filter <name>` — run a single suite or test.
- `open Package.swift` — open in Xcode.

## Architecture

The entire app lives in one file: `Sources/main.swift` (~900 lines). The pieces below describe the cross-cutting design that isn't obvious from a single glance.

### Three SwiftUI scenes, one shared store
`ClipboardVaultApp` declares a `WindowGroup` (full UI: `ContentView` → `SidebarView` + `MainPanelView`), a `MenuBarExtra` (compact `QuickPanelView`), and a `Settings { SettingsView() }` scene. The first two bind to the **same** `@StateObject ClipboardStore`; `SettingsView` reads preferences via `@AppStorage` and creates its own `LaunchAtLoginManager` (`SMAppService` state is process-wide so the two instances stay consistent). On launch the app sets `NSApplication.shared.setActivationPolicy(.accessory)` — menubar app, no dock icon.

### Capture loop
`ClipboardStore` polls `NSPasteboard.general.changeCount` every **1.0 s** via a `Timer` (configurable in Settings via `UserDefaults` key `pollInterval`; takes effect on restart). Before reading values, `checkClipboard()` skips any pasteboard tagged with one of `sensitivePasteboardTypes` (`org.nspasteboard.{Concealed,Transient,AutoGenerated}Type`, `com.agilebits.onepassword`) so password-manager copies never get persisted. Deduplication uses a `lastSignature` string (`"text:<value>"` or `"image:<count>:<prefix.hashValue>"`) — if you change the dedup key, both the text and image branches must agree. Images are converted from `pasteboard.data(forType: .tiff)` to **PNG** via `NSBitmapImageRep` before storage (much smaller). Max history defaults to **200** (`maxEntries`), also configurable via Settings; both the in-memory array and SQLite are trimmed together and a one-shot trim runs at app start.

### Persistence (SQLite, raw C API)
`ClipboardPersistence` opens `~/Library/Application Support/ClipboardVault/clipboard.sqlite` with `sqlite3_open_v2` + `SQLITE_OPEN_FULLMUTEX` + `PRAGMA journal_mode=WAL`. FULLMUTEX is load-bearing: writes come from `@MainActor ClipboardStore`, but `EntryCard.onAppear` reads image data synchronously on main as well — if you ever move BLOB reads to a background queue, keep FULLMUTEX. The init accepts an optional `path:` so tests can point at a temp-dir DB. `SQLITE_TRANSIENT` is hand-defined at the top of the file because the Swift `SQLite3` module doesn't export it. Schema changes go through `runMigrations()` which is gated on `PRAGMA user_version`; append `if current < N { … writeUserVersion(N) }` blocks for new migrations rather than touching the existing baseline.

### Image cache
`ImageCache` (NSCache-backed, `countLimit=60`) sits between `EntryCard`/`copyBack` and `ClipboardPersistence.loadImageData(id:)`. `EntryCard.onAppear` reads the cache synchronously on main — keep it that way unless you can prove the `NSImage` send is Sendable. Invalidate via `imageCache.invalidate(id:)` on entry deletion or `invalidateAll()` on clearAll.

### Global hotkey & window control
`GlobalHotKeyManager` registers `Cmd+Shift+V` via the **Carbon** `RegisterEventHotKey` API (not SwiftUI keyboard shortcuts). The Carbon callback bridges back to Swift via `Unmanaged.passUnretained(self)`. On trigger it:
1. Calls `AutoPaster.shared.capturePreviousApp()` **before** activating ourselves (otherwise frontmostApplication is already us).
2. Calls `WindowController.showMainWindow()` to bring the window to front.

`WindowController` (`@MainActor enum`) is the canonical place for window show/hide; both the hotkey handler and `selectAndPaste` route through it. Window lookup is by title `"ClipboardVault"` — keep `WindowController.mainWindowTitle` and the `WindowGroup("ClipboardVault", id: "main")` literal aligned.

### Keyboard navigation
`MainPanelView` installs an `NSEvent.addLocalMonitorForEvents` for `.keyDown` on appear. `handleKey(_:)` consumes `↑`/`↓`/`Return`/`Esc`, and forwards printable characters into the search field when search isn't already focused (type-to-search). Cmd-modified keys are intentionally not consumed so the toolbar's `Cmd+1..4` filter shortcuts still fire. `selectedIndex` resets to 0 when search text or filter changes, and `ScrollViewReader` auto-scrolls the highlighted card into view.

### Auto-paste
`AutoPaster.shared` (`@MainActor`) holds the previously-frontmost `NSRunningApplication`, captured at hotkey-trigger time. When the user selects an entry and `@AppStorage("autoPasteEnabled") == true`, `selectAndPaste` calls `pasteToPreviousApp()` which re-activates that app and synthesises `Cmd+V` via `CGEvent.post(tap: .cghidEventTap)`. Requires **Accessibility permission** — `AutoPaster.ensureAccessibility()` triggers the system prompt; the `kAXTrustedCheckOptionPrompt` constant is hard-coded as the literal `"AXTrustedCheckOptionPrompt"` because the imported global trips Swift 6 strict-concurrency checks.

### Launch at login + Applications-folder requirement
`LaunchAtLoginManager` uses `SMAppService.mainApp`, which requires the app to be running from `/Applications`. `AppInstaller` detects when the app is running from elsewhere and exposes `moveToApplications()`; `MainPanelView` shows a yellow prompt banner when `isBundle() && !isRunningFromApplications()`. After moving, the running instance terminates and the moved copy launches.

### Smart text rendering
`ClipboardEntry.smartType` classifies text entries as `.url`, `.color` (6-digit `#RRGGBB`), or `.none`. `EntryCard` branches on this to render colour swatches, link icons, or generic text. If you add a new smart type, both `smartType` and `EntryCard`'s switch must be updated.

### Filtering and sorting
`filteredEntries` is the single source of truth for what the main list shows: favourites first, then newest-first, then filtered by sidebar selection (`all`/`text`/`images`/`favorites`), then filtered by `searchText`. Toolbar `Cmd+1..4` switches the sidebar filter. `quickEntries` (used by the menubar panel) ignores filters and just returns the 20 most recent.

## Conventions

- All UI-affecting state mutation must happen on `@MainActor`. `ClipboardStore`, `LaunchAtLoginManager`, `AutoPaster`, `WindowController` are all `@MainActor`-isolated; the polling `Timer` hops back via `Task { @MainActor in … }`.
- SQL identifier comparisons use `LOWER(id) = LOWER(?)` so UUID casing differences don't cause misses — match this when adding new lookups.
- We target macOS 13, so use the **single-parameter** `.onChange(of:perform:)` form, not the macOS 14 two-parameter overload.
- Logging goes through `Log.{db,hotkey,installer}` (`os.Logger`); don't reintroduce `print()`. Mark message interpolations with `privacy: .public` only for non-sensitive strings (paths, error descriptions).
- Don't introduce SwiftPM dependencies casually: the package currently has zero external dependencies and links only the system `sqlite3` library (declared via `linkerSettings` in `Package.swift`).
- Tests use **swift-testing** (`import Testing`, `@Test`, `#expect`), not XCTest — Command Line Tools install ships `Testing.framework` but not `XCTest.framework`.
